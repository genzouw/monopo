## 💡 機能提案の背景

「モノポリー」や「いただきストリート」における強制買収は、買収側の手持ち現金で支払える範囲に限られます。現実の M&A では、買収対象の資産や将来収益を担保にした借入（買収ローン）で、手元資金を超える買収を行う LBO（レバレッジド・バイアウト）が広く使われています。本書は、既存の強制買収を LBO へ拡張し、レバレッジの利点と負債リスクを体験できるようにする提案です。

> 📎 **関連提案との整合性:** 本書の当初案に含まれていた次の要素は、既存の提案・実装と重複するため本書の対象から除外しました。実装時に参照する正規仕様は各参照先とします。
>
> - **空売り・追証・踏み上げ:** `ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md`（リポジトリ直下）に、初期証拠金率40%・維持証拠金率25%・強制決済・残債処理まで定義済みです。
> - **マクロ経済サイクル（景気）と政策金利:** 景気は `src/game/systems/macroEconomy.ts` の `EconomyStatus`・`ECONOMY_FACTORS`・`ECONOMY_TRANSITION_MATRIX` として実装済みです。景気連動の借入金利は `src/game/systems/loan.ts` の `LOAN_INTEREST_RATES` として実装済みです。本書は別系統の「景気指数」を導入しません。中央銀行による量的緩和・引き締めは `ISSUE_PROPOSAL_INNOVATIVE_REALITY_MONEY_GAME.md` で提案済みです。
> - **オプション取引:** `docs/proposals/ISSUE_PROPOSAL_COMPREHENSIVE_ECONOMIC_SIMULATION.md` の「金融派生商品（デリバティブ）とヘッジ」にコール/プットとプレミアムの仕様が定義済みです。
>
> 既存提案に該当がなかった LBO のみを本書の新規性とします。

### 🎯 提案する機能の概要

既存の強制買収（`src/game/economy.ts` の `calculateForceBuyMultiplier`）を拡張し、買収代金のうち手持ち現金で足りない分を、**買収対象エリアを担保とした借入（買収ローン）** で調達できるようにします。買収後は、プレイヤーの手持ち現金から買収ローンを返済していく必要があります。エリアの収益（通行料）が伸びれば返済に回せる現金が増えるため、収益力の高いエリアほど返済しやすくなります。返済が滞るとデフォルトとなり、担保エリアを失います。

### ⚙️ ゲーム内での具体的なメカニクス

1. **買収ローンの組成**
   - 強制買収の支払い時に現金が不足する場合に限り、不足額を買収ローンとして借りられます。
   - 担保は買収対象エリア自身です。他プレイヤーからの借入は担保になりません。
   - 借入可能額の上限は買収価格の 70% とし、残り 30% 以上は自己資金で支払います（全額借入による買収は認めません）。
   - 買収ローンは変動型（`loanType: 'variable'`）とし、`src/game/systems/loan.ts` の `getLoanInterestRate` に従って景気と連動させます。`macroEconomy` が無効、または `economyStatus` がない場合は、既定変動金利 `DEFAULT_LOAN_INTEREST_RATE`（10%）を基準にします。LBO 専用の金利は新設しません。
   - 買収ローンは既存ローンの `Player.loanBalance` とは別のフィールドで管理し、返済 UI・利息計算を既存ローンと分離します。「総債務」（既存ローン＋買収ローン）の上限を設ける場合は両者を合算して判定します。既存ローンの借入上限（総資産の 50%、`MAX_LOAN_TO_ASSET_RATIO`）とは別枠とし、買収ローン側の上限は買収価格の 70% です。
2. **買収後の返済（周回ごとの分割返済）**
   - 返済期間は組成から 4 周（GO マス通過 4 回）とします。「元本」は組成時の借入額（買収ローンの初期残高）を指します。
   - GO マス通過時に、次の請求額を手持ち現金から自動で引き落とします。
     - 当該周の利息 = 残債 × 金利（既存ローンと同じく現金から支払い、残債には加算しません）
     - 最低返済額 = 元本 ÷ 4 + 当該周の利息
     - 請求額 = 最低返済額 + 前周までの延滞額
   - 担保エリアの通行料は通常どおり所有者の現金として受け取るだけで、返済への自動充当は行いません。通行料が発生しない周でも、請求額は期間と残債で決まります。
   - 手持ち現金が請求額に満たない場合は、部分払いを認めます。実支払額 = min(手持ち現金, 請求額)、延滞額 = 請求額 − 実支払額とし、延滞額は次の GO 通過時の請求額に繰り越します。実支払額は利息、元本の順に充当し、残債は元本に充当した分だけ減ります。手持ち現金が 0 円の周は全額が延滞になります。
   - 増資（設備投資）でエリアの収益を伸ばす、不要な資産を売却（リストラ）して返済に充てる、任意で繰上返済する、といった選択ができます。
3. **デフォルト**
   - 延滞が 2 周連続した場合（2 回連続の GO 通過で請求額を全額払えなかった場合）、または返済期間（4 周）の終了時に残債もしくは延滞額がある場合はデフォルトとなります。
   - デフォルト時、担保エリアは家を 0 に戻して未所有の状態に戻し、通常の購入対象になります（強制買収時に `houses: 0` へ戻す既存の `FORCE_BUY` と揃えます）。既存の `propertyStates` には銀行という所有者がないため、貸し手（銀行）名義の状態は新設しません。
   - 担保処分後の残債は、LBO 専用の次の手順で確定します。信用取引の残債定義（評価損 − 証拠金残高）には依存しません。
     1. 担保評価額 = デフォルト確定時点のエリアの売却価格（既存の資産売却と同じ評価。家がある場合は 0 に戻す前の家を含めて評価し、実装時に既存の売却価格計算と揃えます）
     2. 担保評価額を、未払いの延滞利息、延滞元本、残りの元本の順に充当します。
     3. 充当後に残債が残る場合のみ、その額を負債として残します。担保評価額が債務を上回る場合は、超過分をデフォルトしたプレイヤーの現金として返還します。
     4. 手順 3 の残債が残ったプレイヤーについて、`ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md` の自己破産の閾値判定を行います。この判定は担保処分の充当後に行い、閾値判定の対象は充当後の残債とします。

> 返済期間（4 周）・連続延滞の許容回数（2 周）は初期案の数値です。実装時に既存ローン（`src/game/systems/loan.ts` の GO マス通過時の利息処理）との整合とゲームバランスを検証して調整します。

### 🎓 教材としての教育的効果

- **レバレッジの光と影**: 少ない自己資金で大きな買収ができる一方、収益が伸びず返済に回せる現金が足りなければ、負債に押しつぶされることを体験できます。
- **担保と負債の関係**: 借入の担保になるのは、借りる側が保有する（または買収する）資産であることを理解できます。
- **金利の影響**: 景気連動の金利によって、同じ買収でも返済負担が変わることを学べます。

### ⚖️ ゲームバランスへの影響と懸念点

- **ルールの複雑化**: 初心者には買収ローンの概念が重いため、エキスパートモード限定の機能とするか、段階的にアンロックする形が必要です。
- **買収の連鎖と過度な有利さ**: 資金力のあるプレイヤーが借入を重ねて買収を連鎖させると、ゲームの勝敗が早期に決まる恐れがあります。借入可能額の上限（買収価格の 70%）と、総債務の上限による制限を実装時に検討します。
- **理不尽な破産**: デフォルトの連鎖が起きやすくなるため、`ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md` の破産救済の仕組みと整合させる必要があります。
