# 【提案】monopo への現実的・教育的マネーゲーム機能の追加: 伝統的ゲーム性と現代金融システムの融合

## 💡 機能提案の背景

「monopo（モノポ）」を現実の経済の動きやマネーゲームの概念を学習できる「教育的教材」として進化させるための提案です。
従来の「伝統的な不動産取引ゲーム」や「伝統的な株式相乗りゲーム」の枠を超え、現代資本主義の複雑なシステムをシミュレートする機能を提案します。

### 🔗 関連提案との整合性

本書の「M&A・TOB」は、`../../ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md` および `ISSUE_PROPOSAL_ADVANCED_MONEY_GAME.md` にも重複する提案が含まれます。実装時に参照する **TOB の正規仕様は本書**とし、両書の TOB 記述は本書へ委譲します（両書側にもその旨を明記済み）。統合後の結論は以下のとおりです。

- **成立閾値:** 発行済み株式の **50% 超**（`ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md` にあった「2/3 以上」などの別閾値は採用しません）。
- **少数株主:** **スクイーズアウトは行いません**（非応募者は株式をそのまま保有し続けます）。
- **防衛策:** ポイズンピルを採用します（発動条件・希薄化の扱いは本書で定義します）。

なお「信用取引」「タックスヘイブン」「独占禁止法」「インサイダー取引」は本書の対象外であり、正規仕様は引き続き `../../ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md` です。

## 🎯 提案する機能の概要

伝統的な「エリア独占」「株式相乗り」「増資」といった優れたゲームメカニクスをベースとしつつ、さらに現実社会を模倣した、高度で革新的な以下のマネーゲーム機能の導入を提案します。

1. **エリア独占・相乗りとM&A（企業の合併・買収）機能:** 伝統的なエリア独占と株式相乗りを拡張し、他プレイヤーが保有するエリアの株式を市場外で公開買付け（TOB）し、過半数を取得することでエリアの所有権を奪う機能と、その防衛策（ポイズンピルなど）。
2. **インフレ・デフレサイクルと中央銀行の金融政策:** 「市場流通現金量」（後述の唯一の判定指標）に応じてマクロ経済が変動し、中央銀行が政策金利を操作したり量的緩和を行うシステム。
3. **ベンチャーキャピタル(VC)と未上場エリアへの投資:** マップ上の未開発エリア（スタートアップ）に初期投資を行い、将来の「上場」や「ユニコーン化」によって莫大な利益を得るか、倒産リスクを負う機能。
4. **ESG投資とカーボンプライシング:** エリアに環境負荷の概念を導入。炭素税の支払いやESG評価による税制優遇、見せかけの環境配慮（グリーンウォッシュ）発覚時の株価暴落リスクなどを再現。
5. **クラウドファンディングとインフラ共同開発:** 1人では開発コストが重い巨大インフラマスに対し、複数プレイヤーで資金を出し合い、将来の収益を拠出割合に応じて分配する仕組み。

## ⚙️ ゲーム内での具体的なメカニクス

- **エリア独占・相乗りとM&A（TOB）:**
  - プレイヤーはエリアを独占し、設備投資（増資）を行うことで資産価値と通行料を上げます。他プレイヤーはそのエリアの株を買うことで配当や株価上昇の恩恵を受けます。
  - さらに、市場価格以上のプレミアム（時価の1.5倍以上）を提示することで、他プレイヤーのエリアを買収（TOB）可能。防衛側は「ポイズンピル（新株予約権の無償割当て）」などで対抗でき、攻防のマネーゲームが発生します。
  - **TOB の対象**: 買収対象は**エリアの株式のみ**とします。エリア所有権を直接買い取る取引ではなく、「発行済み株式の過半数を取得した者が、そのエリアの所有権を得る」という株式ベースの一本化した仕組みとします（所有権とは別枠の買収は行いません）。
  - **応募条件**:
    - TOB を仕掛けられるのは自分の手番のみ。1手番につき1件まで。
    - 買付価格は「宣言時点の時価 × 1.5」以上の整数（ドル未満切り上げ）とし、買付予定株数（目標株数）を同時に宣言します。目標株数は、成立後に買収者の保有株が発行済み株式の過半数（50%超）となる株数以上でなければ宣言できません。
    - 宣言時に「買付価格 × 目標株数」の全額を買収者の所持金から**エスクロー（供託）**します。所持金が不足する場合は TOB を宣言できません。
    - 対象エリアの株主（防衛側の所有者を含む）は、買収者の次の手番が回ってくるまでの間に、保有株の全部または一部の応募可否を各自1回だけ選択します。無回答は「応募しない」として扱います。
  - **受入株数の確定**: 締切後、応募株のうち実際に買い付ける株数（**受入株数**）を先に確定させ、以降の成立判定・精算・持株比率判定はすべて受入株数を用います（応募株数はそのままでは使いません）。
    - 応募総数が**目標株数以下**の場合: 応募株を全量受け入れます（受入株数 = 応募総数）。
    - 応募総数が**目標株数を超える**場合: **受入株数 = 目標株数**とし、超過分は受け付けません。各応募株主からの受入株数は「目標株数 × その株主の応募株数 ÷ 応募総数」を**1株未満切り捨て**で算出し、切り捨てにより生じた残余株を、応募株数の多い順（同数の場合は手番順）に1株ずつ配分して合計を目標株数に一致させます。この規則により配分は決定的で、同一のゲーム状態からは常に同一の受入株数が再現されます。
    - 按分により受け入れられなかった応募分は、応募しなかった株と同様に、その株主がそのまま保有し続けます。
  - **成立閾値**: 受入株数に買収者の既存保有株を加えた株数が、発行済み株式の**50%超**に達した場合に成立とします。達しない場合は不成立です。
  - **防衛策（ポイズンピル）の影響**: 防衛側は TOB 宣言後・締切前に1回だけポイズンピルを発動できます。発動すると、買収者**以外**の既存株主に対して保有株数と同数の新株が無償割当てされ、発行済み株式総数が増加します。結果として買収者の持株比率が希薄化し、成立閾値（50%超）に必要な応募株数が増えます。発動コストとして、防衛側は「時価 × 発行済み株式総数 × 5%」を銀行へ支払います（支払えない場合は発動できません）。成立判定は**希薄化後の発行済み株式総数**を用いて行います。
  - **少数株主（非応募者）の扱い**: 強制買収（スクイーズアウト）は**行いません**。非応募者（および按分により受け入れられなかった応募分の保有者）は株式をそのまま保有し続け、以後は買収者が所有者となったエリアの株主として、通常どおり配当・株価変動の対象となります。したがって非応募者への補償は発生しません（応募機会を平等に与えることをもって補償に代えます）。
  - **成立時の精算順序**（この順に処理し、途中で失敗しうる処理は含めません）:
    1. エスクローから「買付価格 × 受入株数」を支払い、応募株主それぞれへ「買付価格 × 各自の受入株数」を分配する。
    2. 受入株を買収者へ移転する。
    3. エスクローの残額（買付価格 ×（目標株数 − 受入株数））を買収者へ返金する。受入株数は目標株数を超えないため、残額が負数になることはありません。
    4. 買収者の持株比率が 50% 超であることを確認し、エリアの所有権を旧所有者から買収者へ移転する。旧所有者が保有していた家・設備投資はそのまま買収者に引き継がれます（別途の対価は発生しません）。
    5. 当該エリアの時価を買付価格に更新する。
  - **不成立時の精算**: 応募株の移転・所有権移転は一切行わず、エスクローの全額を買収者へ返金します。同一エリアに対する再 TOB は、不成立から3ラウンド経過後まで宣言できません。
- **インフレ・デフレサイクルと中央銀行:**
  - **判定指標は「市場流通現金量」ただ1つとします。** 物件・株式などの含み資産は判定に用いません（総資産額は判定指標として使用しません）。
    - **定義**: 全生存プレイヤーの所持金の合計（単位: ドル、整数）。破産済みプレイヤーの所持金と、銀行が保有する現金は含めません。
    - **評価タイミング**: 1ラウンド（全生存プレイヤーが1手番ずつ終えた時点）の終了時に1回だけ評価します。ターン中の一時的な増減では景気は変動しません。
    - **基準値**: 判定には**生存プレイヤー1人あたりの平均現金**を用います。評価時点の市場流通現金量を `M`、その時点の生存プレイヤー数を `N`、ゲーム開始時の初期所持金（人数に依存しない定数）を `C0` として、比率 `R = (M / N) / C0` で判定します。
    - **人数変動への追従**: `R` は**生存者1人あたりの平均現金**を基準値とするため、破産によって生存プレイヤー数が減ると、破産者の所持金が生存者平均を下回っていた分だけ `R` は**上昇します**（例: `C0 = 100`、所持金が `100, 100, 100, 0` の4人では `R = 0.75`。0ドルのプレイヤーが破産すると `M = 300` / `N = 3` となり `R = 1.0`）。これは仕様として意図した挙動で、「破産者を除いた**生存者の手元がどれだけ潤っているか**」を景気判定の基準とし、その変化によって景気状態が変わり得ることを許容します。分母を「初期所持金 × 参加人数」でゲーム開始時に固定すると、分子だけが人数減少の影響を受け、**破産が起きるほど `R` が下がって終盤が金融危機に張り付く**（＝勝負がつくほど景気が悪化する）逆向きの挙動になります。加えて `ECONOMY_FACTORS.crisis = 0.4` で通行料が4割まで落ちるため、劣勢プレイヤーの数少ない逆転手段まで同時に潰れます。これを避けるため1人あたり平均で正規化します。
  - **既存実装との関係**: 既存の `src/game/systems/macroEconomy.ts` は、`ECONOMY_TRANSITION_MATRIX`（マルコフ連鎖の遷移確率）・`transitionEconomy(current, random)`（確率的遷移）・`shouldUpdateEconomy(turnCount)`（`ECONOMY_UPDATE_INTERVAL = 5` ターンごとの更新）で構成されています。本提案はこれらを**置き換えません**。`R` は決定的な景気判定式としてではなく、**既存の遷移確率に加えるバイアス**として作用させます。
    - この方針により、`ECONOMY_TRANSITION_MATRIX` / `transitionEconomy` / `ECONOMY_UPDATE_INTERVAL` は死にコードにならず、既存テストも維持されます。乱数由来の意外性も残ります。
    - `features.macroEconomy` が OFF のときは既存挙動と完全互換です。ON のときはバイアス分だけ遷移確率が変わるため、この差分は実装時に既存テストの期待値へ反映します。
  - **更新タイミング**: 景気状態の更新は従来どおり `shouldUpdateEconomy(turnCount)` に従い、`ECONOMY_UPDATE_INTERVAL = 5` ターンごとに `transitionEconomy()` で遷移させます。`R` は直近のラウンド終了時に算出済みの値を用います。
  - **`R` による遷移確率バイアス**（既存の `features.macroEconomy` の4状態に対応、評価は上から順に最初に一致したものを1つだけ適用）:
    - `R >= 1.5` → 遷移先 `boom`（好況・インフレ）の確率に `+0.15`
    - `1.5 > R >= 0.8` → バイアスなし（`ECONOMY_TRANSITION_MATRIX` の値をそのまま使用）
    - `0.8 > R >= 0.5` → 遷移先 `recession`（不況・デフレ）の確率に `+0.15`
    - `R < 0.5` → 遷移先 `crisis`（金融危機）の確率に `+0.15`
  - **バイアス適用後の正規化**: 加算により行の合計が 1.0 を超えるため、加算対象を除く他の遷移確率を元の比率で按分して減算し、合計を 1.0 に戻します。**元の確率が 0 の遷移（例: `boom → crisis`）は 0 のまま**とし、バイアス対象がそれに該当する場合はバイアスを適用しません。これにより `transitionEconomy()` が前提とする「確率 0 の状態はスキップする」性質を崩しません。
  - 中央銀行は上記の景気状態に応じて政策金利を発表し、金利が高いと借入コストが増大して株価が下落、金利が低いと投資が活性化するマクロ経済の波を作り出します。
- **VCと未上場エリアへの投資:**
  - 「未上場企業」マスに止まると安価で投資が可能です。未上場フェーズの間は他プレイヤーが止まっても配当は発生しません。
  - **投資額と持分**: 投資額は「そのマスに設定された基準投資額」の固定額とし、1マスにつき最大4口まで（1プレイヤー1口まで）出資できます。**投資持分は出資口数の均等割**とします（例: 3人が出資した場合、各自 1/3）。出資後の追加出資・持分の売買は行いません。
  - **判定タイミング**: 最初の出資が行われたターンを起点とし、**その5ターン後の同一プレイヤーの手番開始時**に1回だけイベント判定を行います（判定は1マスにつき1回のみ、以後は状態が確定します）。
  - **判定式**: `getSecureRandomInt(0, 99)` の戻り値 `n` を用い、`n < 40` なら**上場**、それ以外（`n >= 40`）なら**倒産**とします（上場確率 40%、倒産確率 60%）。判定は景気状態やプレイヤー人数に依存しません。
  - **上場時**: エリア価値が「**基準投資額 × 20 × 出資口数**」に置き換わります（既存の通常配当への加算ではなく、配当算定基準となるエリア価値そのものが置き換わります）。**元本は返還しません**（出資分はそのまま持分に転化します）。**判定ターンの次のターンから配当を開始**し、他プレイヤーが止まった際の通行料を、出資者へ持分に応じて分配します。
    - **口数比例とする理由**: エリア価値を口数に依存しない固定額（基準投資額 × 20）とすると、後から出資した分だけ既存出資者の取り分が削られます（単独出資なら 20 倍を独占、4人出資なら 1/4）。すると「自分から先に出資せず、他人が出資したマスに後乗りする」が支配戦略になり、全員がそう考えて誰も1番目にならず機能が起動しません。倒産確率 60% のリスクを最初に引き受けた人がいちばん報われない構造は、「先行投資はリスクを取った分だけ報われる」という教材としての学びとも逆になります。口数比例にすることで、1人あたりの期待リターンが出資人数に依存せず単独出資と等しくなり、このチキンレースが消えます。
  - **倒産時**: エリア価値は 0 となり、投資額は全額失われます。**判定ターン以降、当該マスでは配当は一切発生しません**（配当終了）。以後そのマスへ止まっても支払いは発生しません。
  - **端数処理**: 配当額は「通行料 × 持分」を計算し、**ドル未満は切り捨て**て各出資者へ支払います。切り捨てにより生じた残額は銀行に繰り入れます（出資者間で再分配はしません）。この規則により、同一ゲーム状態からは常に同一の支払額が再現されます。
- **ESG投資とカーボンプライシング:**
  - 「化石燃料エリア」などの環境負荷が高いマスは高い収益を上げますが、定期的に炭素税が徴収されます。
  - 「再生可能エネルギーエリア」はESGスコアが高く補助金を得られます。ただし監査イベントで不正が発覚すると罰金が発生します。
- **クラウドファンディングとインフラ共同開発:**
  - 特定の巨大プロジェクトマスに対して各プレイヤーが資金を拠出します。プロジェクトは以下の**5状態**を持ち、遷移は一方向のみ（後戻りしません）とします。

    | 状態       | 内容                                                   | 次の遷移                                                         |
    | ---------- | ------------------------------------------------------ | ---------------------------------------------------------------- |
    | **募集**   | 出資を受け付けている。資金はロックされる               | 目標金額到達で **成立**／募集期限（10ラウンド）到来で **不成立** |
    | **成立**   | 目標金額に到達し、募集を締め切った状態                 | 締切と同一処理内で超過分を返金し、直ちに **開発中** へ           |
    | **開発中** | 出資金を投入して建設中。出資受付は行わない             | 成立から3ラウンド経過した時点で **完成**                         |
    | **完成**   | エリアが稼働し、通行料の配当が発生する                 | 終端状態                                                         |
    | **不成立** | 期限内に目標未達。集まった資金は持分比率で按分返金済み | 終端状態                                                         |

  - **募集締切と超過分の返金**: 目標金額に達した時点で即座に募集を締め切ります（**成立**）。目標額を超過した出資分は各出資者の出資比率に応じて按分・返金します（**ドル未満は切り捨て**とし、切り捨て分は銀行に繰り入れます）。
  - **不成立の判定と返金**: 募集開始から10ラウンド以内に目標金額へ到達しなかった場合、その10ラウンド目の終了時に**不成立**とし、集まった資金の全額を、その時点の**持分比率（後述の破産による再配分を反映した最新の比率）に応じて残存出資者へ按分**して返金します（**ドル未満は切り捨て**とし、切り捨て分は銀行に繰り入れます）。
    - **「各自の拠出額そのまま」返金としない理由**: 破産した出資者の拠出分は没収され、持分だけが残存出資者へ再配分されます（現金は動きません）。このとき返金基準を拠出額のままにすると、破産者が拠出した現金だけが精算されずに残り、「集めた資金の総額 = 返金額の総額 + 銀行への繰入額」という収支が閉じません。持分比率で按分すれば破産者の拠出分も自動的に残存出資者へ返り、総額が閉じます。
  - **途中撤退の禁止**: 出資後、**完成**に至るまでの途中撤退は認めず、資金はロックされます。
  - **完成前の破産処理**: **募集**・**成立**・**開発中**のいずれかの状態で出資者が破産した場合、その出資分は没収し、**残存出資者の（破産者を除いた）出資比率に応じて持分を再配分**します。再配分による現金の移動は発生しません（没収された出資額は他の出資者の持分に転化します）。
    - **残存出資者が1人もいなくなった場合**: プロジェクトは**不成立**へ遷移し、資金は銀行に没収されます。当該マスは未開発状態に戻り、以後あらためて**募集**を開始できます。
  - **最終出資台帳の確定**: **完成**へ遷移する時点で、その時点の持分を「**最終出資台帳**」として確定・凍結します。以後の破産・資産変動によって最終出資比率が変わることはありません。
  - **完成後の配当順序**: 完成した次のターン以降、他のプレイヤーが止まった際の通行料を、**最終出資台帳の比率に基づいて**システムが自動で分配します（**ドル未満は切り捨て**、切り捨て分は銀行に繰り入れます）。すなわち「① 破産処理による持分の再配分 → ② 完成による最終出資台帳の確定 → ③ 次ターン以降の通行料配当」の順に処理が確定します。

## 🎓 教材としての教育的効果

- 伝統的な不動産取引ゲームの基礎（複利効果、投資による資産拡大）を学びつつ、現代のM&Aや敵対的買収の脅威、防衛策の仕組みを実践的に学べます。
- マクロ経済の波（インフレ・デフレ・金利）が個人の資産や企業の価値にどう影響を与えるか、中央銀行の役割をゲーム内で体感できます。
- VC投資を通じたハイリスク・ハイリターンの仕組みや、スタートアップのエコシステムを理解できます。
- 現代の企業に求められる環境配慮（ESG）の重要性と、それに伴うコスト（炭素税）、企業のコンプライアンスリスクを学べます。
- クラウドファンディングによる資金調達の手法と、利益分配の仕組みを体験できます。

## ⚖️ ゲームバランスへの影響と懸念点

- 要素が多岐にわたるため、ゲームのルールが非常に複雑になり、初心者にとって学習コストが高くなる懸念があります。
- 対策として、最初は「ベーシックモード（伝統的なエリア独占と株式相乗りのみ）」でプレイさせ、習熟度に応じて「アドバンスドモード（M&A、中央銀行、ESGなど）」の革新的な機能を徐々にアンロックするチュートリアル機能の実装を推奨します。
- **解放単位**: 解放状態は**この端末（ブラウザ）単位**で管理します。プレイヤー個人のアカウントは存在せず、また1ゲーム限りでリセットされることもありません。**複数ゲームをまたいで累積**する端末単位の進捗として扱います。
- **解放条件**（各機能は独立に判定し、条件を満たした時点で恒久的に解放されます）:

  | 解放される機能                          | 解放条件（いずれも累積値で判定）                              |
  | --------------------------------------- | ------------------------------------------------------------- |
  | 株式（`features.stocks`）               | ベーシックモードのゲームを1回、最後（勝敗確定）までプレイする |
  | 景気サイクル（`features.macroEconomy`） | 株式解放後、株式の売買を通算10回以上行う                      |
  | クラウドファンディング・VC              | 景気サイクル解放後、ゲームを通算3回、最後までプレイする       |
  | M&A（TOB）・ESG                         | 上記すべて解放後、ゲームに通算1回以上勝利する                 |

- **評価方法**: 上記の判定に用いる累積値は「完走ゲーム数」「勝利数」「株式売買回数」の3つの整数カウンタのみとし、途中離脱したゲームはカウントしません。判定は各ゲームの終了時（勝敗確定時）および株式売買の成立時に行い、条件を満たしたカウンタに対応する機能フラグを `true` に更新します。
- **永続化**: これらのカウンタと解放済みフラグは `localStorage` の `monopo-progress` キーに保存し、再起動後も解放状態を復元します。既存の `monopo-save` / `monopo-setup` と同様に、**読み込み時は信頼できない入力として構造を深くバリデーション**し（各カウンタが有限の非負整数か、各フラグが `boolean` か）、不正な値を検出した場合は当該項目を初期値（カウンタ `0` / フラグ `false`）にフォールバックします。
- **検証可能性**: 上記はすべて整数カウンタと閾値の比較のみで判定できるため、ユニットテストで解放境界（閾値の直前・直後）を再現可能に検証できます。
