## 💡 機能提案の背景

「monopo（モノポ）」を現実の資本主義社会の動きから学べる「教育的教材」として進化させるための提案です。
従来の不動産取引ゲームや資産運用ボードゲームが持つ「不動産取引」「株価相乗り」「エリア独占」「増資」といった基本システムを踏襲しつつ、現代の金融市場・企業買収・金融政策といった要素をゲーム内に取り込みます。

> 📎 **既存実装との整合性:** 「景気サイクル」は `features.macroEconomy`（`src/game/systems/macroEconomy.ts`）として、好況・通常・不況・金融危機の4状態を `ECONOMY_TRANSITION_MATRIX` で遷移させ、`ECONOMY_FACTORS`（好況1.3・通常1.0・不況0.7・金融危機0.4）を通行料などに乗じる形ですでに実装済みです。「中央銀行による金利操作」に相当する景気連動金利も `features.loan`（`src/game/systems/loan.ts` の `LOAN_INTEREST_RATES`）としてすでに実装済みです。また「スタートアップ投資」も `features.altAssets`（`src/game/systems/altAssets.ts` の `resolveVCInvestment`）として、単独プレイヤーによるVC投資（サイコロ2個の合計が10以上でユニコーン成立・10倍払い戻し、2以下で倒産、それ以外は1.5倍または0.5倍の部分回収）がすでに実装済みです。これら既存実装に対して本書が持ち込む新規差分は、後述の政策金利の上乗せ1点のみです。
>
> 📎 **関連提案との整合性:** 「信用取引と空売り」「M&A・TOB」は、リポジトリルート直下の `ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md`（初期証拠金率40%・維持証拠金率25%・スクイーズアウト・ポイズンピル等を数値まで定義）を正規仕様とし、本書は固有の差分を持ちません（TOBの買付対象を応募株式に限り、応募されなかった株式の強制取得（スクイーズアウト）を別手続とする整理は、本PRで正規仕様側の `ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md:11` に反映済みです）。「スタートアップ投資の共同出資（クラウドファンディング）化」は `docs/proposals/ISSUE_PROPOSAL_INNOVATIVE_WEALTH_SIMULATION.md` を正規仕様とし、本書では新規提案として扱いません。

### 🎯 提案する機能の概要 (What)

従来の不動産取引ゲームやいただきストリートなどの「不動産取引」「株価相乗り」「エリア独占」「増資」の概念をベースとしつつ、さらに現代の現実的な資本主義社会を模倣し、マネーゲームの教材として効果的な機能を扱います。既存の正規仕様・既存実装との重複を避けるため、本書が**新規提案として持ち込む差分は以下の1点**に限定します。

1. **景気連動金利に「政策金利」の軸を追加する（新規差分）**：現行の `LOAN_INTEREST_RATES`（好況5%・通常10%・不況15%・金融危機25%）は、不況・金融危機ほど金利が上がる信用リスク型のモデルで、他の提案書（`ISSUE_PROPOSAL_MODERN_CAPITALISM_SIMULATION.md` 等）もこのテーブルを置き換えない前提としている。本書はこのテーブルを反転・置換せず、**好況局面に限り中央銀行の利上げに相当する政策金利の上乗せ**を追加で発生させる。これにより、既存テーブルの信用リスクの方向性（不況・金融危機ほど高金利）を保ったまま、好況時は不動産収入が増える一方で新規借入のコストも上がるというトレードオフを新たに成立させる。

なお、以下は本書では新規提案として扱わず、上記の前提として参照するに留めます。

- **信用取引と空売り（ショート）**：正規仕様は `ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md`。本書は固有の差分を持たない。
- **M&A・TOB**：正規仕様は `ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md`。TOBの買付対象を応募株式に限り、応募されなかった株式の取得（スクイーズアウト）を別手続として扱う整理は、本PRで正規仕様側（`ISSUE_PROPOSAL_ADVANCED_STOCK_SYSTEM.md:11`）に反映済みのため、本書は固有の差分を持たない。
- **スタートアップ投資・クラウドファンディング**：単独VC投資は `resolveVCInvestment` として実装済みで、共同出資への拡張は `docs/proposals/ISSUE_PROPOSAL_INNOVATIVE_WEALTH_SIMULATION.md` が正規仕様。本書は固有の差分を持たない。

### ⚙️ ゲーム内での具体的なメカニクス (How)

- **景気サイクルと政策金利の上乗せ（差分部分のみ）**：好況・通常・不況・金融危機の遷移、景気乗数による不動産収入の増減、および `LOAN_INTEREST_RATES` の各局面の金利水準（好況5%・通常10%・不況15%・金融危機25%）は既存実装（`macroEconomy.ts` / `loan.ts`）のまま変更しない。本書の差分は、**好況局面でローンを新規に組む場合のみ**、中央銀行の利上げに相当する政策金利（例: +3〜5ポイント）を上乗せする点。不況・金融危機・通常局面の金利や、固定金利（`FIXED_LOAN_RATE`）は変更しない。
  - **上乗せは組成時点で固定し、既存ローンには波及させない（仕様の要点）**：現行の `getLoanInterestRate(state, player, loanType)` は呼び出し時点の `state.economyStatus` だけから金利を算出し、GOマス通過時の利息計算（`reducer.ts` の `calculateInterest(player.loanBalance, getLoanInterestRate(...))`）もこの関数を毎回現在のゲーム状態で呼び出す。また `Player` は `loanBalance`（全借入の合算値）と `loanType` しか保持しない。そのため上乗せを `getLoanInterestRate` の内部に加えると、**好況になった時点で既存の変動金利ローン残高にまで上乗せが波及してしまい、「新規ローンのみ」という条件が成立しない**。
  - **したがって、上乗せ分は残高とともに保存する**：`Player` に組成時に確定した上乗せ率 `loanPolicySurcharge?: number` を追加し、借入アクション（`TAKE_LOAN`）の時点で「そのとき `economyStatus === 'boom'` なら `POLICY_RATE_SURCHARGE`、それ以外は 0」を確定させる。`loanBalance` は個別ローンを持たない合算値のため、既存残高と新規借入額による**加重平均**で更新する（例: `newSurcharge = (oldBalance * oldSurcharge + newAmount * originationSurcharge) / (oldBalance + newAmount)`）。これにより既存残高ぶんの上乗せは 0 のまま保たれる。
  - **利息計算での適用と後始末**：GOマス通過時の実効金利は `getLoanInterestRate(...) + (player.loanPolicySurcharge ?? 0)` とし、`getLoanInterestRate` 自体は現行仕様（現在の景気状態から再計算）を変更しない。`REPAY_LOAN` で `loanBalance` が 0 になった場合は `loanType` と同様に `loanPolicySurcharge` も `undefined` に戻す。固定金利ローン（`loanType === 'fixed'`）は上乗せ対象外とし、常に 0 とする。永続化データから復元する際は、`loanPolicySurcharge` が 0 以上の有限数であることを検証してから state に適用する。
  - これにより、既存テーブルの「不況・金融危機ほど金利が高い」という信用リスクの方向性と、他の提案書が前提とする「`LOAN_INTEREST_RATES` を置き換えない」という制約の両方を保ったまま、好況時は不動産収入が増える一方で**新規借入のコストだけ**が上がるというトレードオフが生まれる。

### 🎓 教材としての教育的効果 (Why it is educational)

- **マクロ経済と金融政策の体感**：景気過熱時（好況局面）に中央銀行が利上げする政策金利の上乗せを新規借入にのみ発生させることで、好況期でも借金の返済コストが上がりうること、および景気を冷ますという中央銀行の役割を、既存の信用リスク型金利（不況・金融危機ほど高金利）を壊さずに体感できる。

### ⚖️ ゲームバランスへの影響と懸念点

- 初心者にとって機能が複雑になりすぎる恐れがあるため、「ベーシックモード」と「アドバンスドモード（教材モード）」に分け、段階的に機能をアンロックするなどの工夫が必要。
- 政策金利の上乗せ幅（例: +3〜5ポイント）が大きすぎると、好況時の新規借入が既存の固定金利（`FIXED_LOAN_RATE`）より著しく不利になり、変動金利を選ぶ意味が薄れる。既存テーブルを反転させない設計のため、金融危機局面が「金利・収入の両面で最も厳しい」という現行の緊張関係（死亡フラグ）はそのまま維持されるが、上乗せ幅は `FIXED_LOAN_RATE` の水準と整合するよう別途調整が必要。
